## 수치 및 Lean 증거

- 준비 문서의 404점 검증 스크립트를 다시 실행했다. 404/404가 스케일 오차 기준 10⁻⁸을 만족했다. 최댓값은 7.71793×10⁻¹¹, 최대 절대 오차는 3.60977×10⁻¹⁰이었다.
- 제품 모듈을 480점에서 독립 mpmath 값과 대조했다. 위 404점에 별도의 시드와 경계점 76점을 추가했다. 최대 스케일 오차는 7.717929×10⁻¹¹, 최대 절대 오차는 4.3149728×10⁻¹⁰이었다. 첫 60개 높이를 재계산했으며 최대 차이는 1.3272×10⁻¹⁴였다. 복소 거듭제곱으로 계산한 명시적 공식 20건과 SymPy/mpmath 계량 10건을 모두 대조했다. [수치 기준과 수정 근거](NUMERICS.md)
- 09장은 오른쪽 연속 ψ와 점프에서 좌우 평균을 택하는 ψ₀를 함께 보여 준다. 구간 오차 지표는 같은 0.25 간격의 ψ₀ 표본과 비교한다. 320px에서 x=1000과 N=60일 때 SVG 축 레이블의 경계도 확인했다. 유한 절단의 오차는 구간과 x에 따라 달라진다. [09장 검증 기록](evidence/chapter-09/README.md)
- Lean v4.35.0과 Mathlib `56a005855ea17e0b0958f73ec801ae140b0a1679`에서 실습 소스를 실행했다. 성공 파일은 종료 코드 0, 실패 파일 두 개는 각각 1이었다. 실습은 해당 실행의 `trace_state`, 타입 오류와 `#print axioms` 출력을 사용한다. [실행 로그와 재현 소스](evidence/lean-fixtures.md)
- Proof Explorer의 단축본은 `lsernau/grh-lean`의 `72fead102f663d5c7a407964a13dc0cf9d977207`을 고정한다. 최초 공개본의 소스 링크는 공개 아카이브를 보존한다고 밝힌 커뮤니티 미러를 사용한다. ## 세 차례 검토

1. **콘텐츠와 수학.** 자료 수록 여부, 52개 답의 근거, 제타의 정의역과 극, ψ₀의 점프 규약, 실제 영점과 가상 영점을 검토했다. 84의 인수분해 해설을 정정했고, 소수 현미경의 비교 구간 폭을 정확히 기술했다. 복소 제타 한 기준값을 독립 재계산으로 교체했다. 오래된 V1 메모의 성장률 문장을 고치고 11장 원고를 실제 실행 소스에 맞췄다. 12장과 증명 탐색기의 비영점성 조건은 고정된 Lean Statements와 대조했고 readable 검증 기록의 날짜와 상태를 갱신했다.
2. **디자인과 인터랙션.** 09장에서 실제 브라우저로 게이트를 먼저 검증했다. 모바일에서 그래프에 닿기까지 길었던 안내와 중첩을 줄이고 원고의 관찰 절차를 펼쳐 읽을 수 있게 옮겼다. 차례의 숫자 줄바꿈, 파동 축 눈금, 인수분해 잎의 좁은 배치와 간격 히스토그램 눈금 문제를 실제 캡처에서 발견해 보정했다. 07장은 계산한 입력 지도와 출력 복소평면을 나란히 설명한다.
3. **통합과 신뢰성.** 정적 생성 결과의 탐색, 학습 상태, 실험 링크, 확대 창과 Escape 포커스 복귀를 실제 Pages 아티팩트에서 검증했다. 01-B에서 숫자 선택값이 문자열로 전달되던 문제와 04-B의 기본값 유효성 문제를 고쳤다. 모든 실험의 초기 상태에 오류가 없어야 한다는 통합 검사를 추가했다.

## 로컬에서 읽기와 검증

의존성이 없는 Work 08만 생성해 읽으려면 저장소 루트에서 다음을 실행한다.

```sh
node riemann-lean/v2/book/build.mjs
python -m http.server 3000 --directory riemann-lean/dist
```

`http://localhost:3000/`에서 읽고, 대표 실험은 `/chapter-09/#09-a`에서 바로 연다. 홈과 나머지 Work를 포함한 배포 구조를 검토하려면 `npm run install:ci` 후 `npm run build:pages`를 실행한다. `dist-pages`는 `/build-canvas/`에서 서빙하도록 구성한 정적 아티팩트다. 아래 Chromium 검사는 그 경로를 임시 HTTP 서버에 만들어 검사한다.

```sh
npm run lint
npm test
node --test riemann-lean/v2/tests/*.test.mjs
python docs/riemann-lean/textbook-v2/reference/check-zeta.py
python riemann-lean/v2/tests/check-core-oracle.py
npm run build:pages
python docs/riemann-lean/textbook-v2/reference/check-browser.py
```

수치 오라클은 mpmath 1.3.0과 SymPy 1.14.0, 브라우저 검사는 Python Playwright와 Chromium을 사용한다. `--output` 및 `--gallery`로 화면 증거를 다시 저장할 수 있다.

## 알려진 한계

- 수치 검증은 지원 범위 내 표본 비교를 의미한다. 제타 수치의 전체 영역에 대한 엄밀한 구간 오차 판정은 제공하지 않는다. 높이 80 초과의 영점은 참조 데이터다. 파동 실험실의 그래프 창은 2–1000이며 실제 참조 영점은 60쌍이다.
- 증명 탐색기의 간선은 단축본에서 명명된 17개 참조이며 다른 판본과 전체 DAG의 간선은 제공 범위 밖이다. 일부 중간 선언은 정의 위치까지 추적하지 않고 출현 근거를 표시한다. 전체 형식 증명의 검증은 MIT의 공개 검사에 귀속한다. 프로젝트에서 실행한 범위는 소규모 Lean 실습이다.
- 학습 기록은 브라우저에서만 유지된다. 내장 브라우저나 운영체제에 따라 시스템 한국어 글꼴이 달라질 수 있다.

- 브라우저 접근성 검증은 Chromium의 역할, 키보드·터치 입력 및 대비를 대상으로 했다. 다른 브라우저 엔진과 실제 보조기기 조합은 이번 검증 범위 밖이다.
