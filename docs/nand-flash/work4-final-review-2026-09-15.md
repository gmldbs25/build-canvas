# Work4 마무리 종합 검토

검토일: 2026-09-15

후속 방향(2026-09-16): 사용자는 반복적인 버튼 조작보다 보는 것만으로 이해할 수 있는 자동 루프를 선호했다. 아래의 단계별 조작 제안은 자동 설명을 기본으로 하고 직접 조작은 선택적으로 제공하는 방향으로 조정했다. 구현 기록은 `work4-watch-loops.md`를 참고한다.

## 총평

현재 Work4는 컴퓨터의 저장 경험 → NAND 구조 → Cell의 물리 → 주소·공간 관리 → 오류 복구 → 다시 문서로 돌아오는 이야기 구조가 완성되어 있다. 22개 장면과 13개 Article 절의 범위도 충분하다. 최종 개선은 핵심 실험의 해석을 일관되게 만들고, 사용자가 변화 과정을 자기 속도로 관찰하며, 학습 후 다시 찾아보기 쉽게 만드는 데 집중하는 것이 좋다.

아래 항목 중 ‘확인된 불일치’와 ‘동작 확인’은 현 구현에서 확인한 사실이다. 나머지는 학습 효과·디자인·자료 활용성에 대한 개선 제안이다. 제품 소스는 수정하지 않았다.

## 유지할 강점

- 처음의 기억.txt로 돌아오는 서사 덕분에 소자 물리와 Software가 하나의 문제로 연결된다.
- 청회색 계열, 절제된 강조색, 기능을 설명하는 공학 도식이 일관된다. 구조 탐험과 후반 실험의 화면 구성이 구분되어 있다.
- FTL과 GC가 같은 저장 상태를 사용하며, 복사 → 주소 갱신 → Erase 순서를 실제 모델로 보여준다.
- 저장 버튼과 영속화, Page와 물리 Cell, 상대 전압과 실제 측정값, SECDED와 실제 SSD ECC의 차이를 명시한다.
- Article은 주제별 기술 출처와 본편 복귀 경로를 제공하고, JavaScript 없이 읽을 수 있는 HTML을 갖춘다.

## A. 마무리 전에 우선 반영할 항목

### 1. Read와 Read Retry의 Vth·bit 판정 규칙 통일

**구분: 확인된 불일치 / 내용 정확성 / 우선순위 높음**

앞선 Read 장면은 `Vref > Vth → 도통 → 1`이라고 설명하지만, Retry의 `sampleBits()`는 `Vth > Vref → 1`로 계산한다. 부호 정의를 달리할 수는 있으나 현재 자료에는 그 전환을 설명하는 내용이 없다. 같은 전압 원리를 이어 배우는 자료 안에서 해석이 반대가 된다.

Retry 예시의 계산 자체는 Vref 0.50에서 2 bit 오류, 0.72에서 검사 통과로 작동한다. 그러나 그림의 점은 61%, 82%로 고정되어 실제 계산에 사용한 Cell 값과 일치하지 않는다. 현재 shift 0.34의 실제 값은 0.475, 0.611, 1.035, 1.171이다.

**개선:** 두 장면이 하나의 전압 판정 함수를 공유하도록 하고, 오류가 난 bit와 해당 Cell의 Vth를 같은 그래프에서 연결한다. 전압 기준이 이동하기 전/후에 어떤 bit가 바뀌었는지 남겨 둔다. 두 실험 사이의 일관성을 확인하는 검증도 추가한다.

근거: `projects/nand-flash/main.js:110`, `model.mjs:99`, `diagrams.mjs:140`. 연결된 [KIOXIA Cell 설명](https://www.kioxia.com/en-jp/rd/technology/nand-flash.html)도 낮은 Vth·도통 상태를 1로 설명한다.

### 2. FTL·GC를 한 단계씩 멈춰 관찰할 수 있게 하기

**구분: 학습 경험 개선 / 우선순위 높음**

FTL의 중간 단계는 1.2초, 1.1초 간격으로 진행되고 GC는 1.2초, 1.1초, 1초 간격으로 진행된다. 사용자는 Page 색, 데이터 버전, 주소 연결, 설명을 동시에 읽어야 한다. 모바일에서는 실행 버튼과 결과가 한 화면에 모두 보이지 않을 수도 있다.

**개선:** 첫 실행에서는 `다음 단계`로 진행하고, 익숙한 사용자가 자동 진행을 선택할 수 있게 한다. 마지막 Write/Read 장면의 수동 단계 조작과도 일관된다. `이전 주소 → 새 주소`, `Valid / Invalid / Free 전후 개수`를 고정해 변화의 결과를 비교하게 한다.

근거: `projects/nand-flash/main.js:249`, `main.js:260`; 데스크톱·모바일 FTL 실행 확인.

### 3. Wear Leveling 비교의 출발 조건 맞추기

**구분: 학습 비교 조건 개선 / 우선순위 높음**

현재 안내는 분산을 끄고 실행한 다음, 켜고 다시 실행하도록 한다. 결과가 누적되므로 동일한 작업량의 비교가 아니다.

| 실행 | Block별 횟수 |
|---|---|
| 초기 상태 | 2, 3, 1, 2, 0, 1 |
| 분산 없이 6회 | 8, 3, 1, 2, 0, 1 |
| 위 상태에서 분산하여 추가 6회 | 8, 3, 3, 3, 2, 2 |
| 같은 초기 상태에서 분산하여 6회 | 3, 3, 3, 2, 2, 2 |

**개선:** 같은 초기값에서 같은 6회를 실행한 두 결과를 비교한다. 최소 수정은 ‘초기화 → 분산 켜기 → 6회’로 안내하는 것이다. 더 좋은 방식은 두 결과와 최대·최소 사용량 차이를 나란히 보여주는 것이다. 이미 생긴 마모는 되돌아가지 않는다는 설명도 결과에 맞춰 붙인다.

근거: `projects/nand-flash/content.mjs:48`, `main.js:296`, `model.mjs:102`.

### 4. 자동 재생 중 키보드 탐색 보호와 ECC 안내 상태 정리

**구분: 동작 확인 / 접근성·상태 문구 개선**

- 자동 재생 시작 후 Tab을 눌러 목차로 포커스를 옮겨도 `aria-pressed="true"`가 유지된다. 사용자가 조작부를 찾는 중에도 장면이 계속 진행한다. Tab 또는 사용자 포커스 진입으로 재생을 멈추도록 한다.
- ECC의 ‘전압 판정 오류 예시’를 누른 뒤 두 bit가 바뀌어도 결과 제목이 ‘오류를 만들어 보세요’로 남는다. ‘오류 예시 준비됨 · 판정 확인 전’처럼 현재 상태에 맞춰 바꾼다. Retry 성공 뒤 직접 해보기 안내도 완료된 관찰 결과에 맞춰 갱신하면 좋다.

근거: `projects/nand-flash/main.js:339`, `diagrams.mjs:139`, `main.js:127`; 브라우저에서 각각 재현.

## B. 디자인·읽기 경험 개선

### 5. 도식의 보조 글자와 상태 식별성을 높이기

**구분: 시각 검토 / 우선순위 중간**

1280×720에서는 전체 분위기와 배치는 안정적이지만 도식 안 주소·축·주석이 작다. 모바일 ECC의 ‘검사/데이터’ 표기는 9px, bit 번호는 10px이다. FTL의 Page 주소도 모바일에서 9px이다. 특히 ‘검사/데이터’는 실험 의미를 이해하는 데 필요한 구분이다.

**개선:** 핵심 라벨은 화면에 실제 표시되는 크기를 기준으로 키운다. 도식의 글자를 모두 확대하기보다 반복되는 보조 라벨을 외부 범례로 옮기고, 선택한 Page의 주소·버전·상태는 별도 큰 글자로 보여준다. 배경과 색 체계는 유지하면서 선택·오류·이동 상태의 대비를 조정한다.

근거: `projects/nand-flash/style.css:93`, ECC 모바일 스타일; 390×844에서 DOM 글자 크기와 화면 확인.

### 6. 작은 모바일에서 설명과 실험을 더 가깝게 배치하기

**구분: 시각 검토 / 우선순위 중간**

390×844의 FTL·ECC는 내부 스크롤로 전체 내용을 볼 수 있다. 다만 결과를 보려면 추가로 내려가야 한다. 320×568 ECC에서는 제목·설명·배경·안내가 첫 화면 대부분을 차지하고, 조작부가 하단에서 시작해 bit 배열은 다음 화면에 나온다. 수평 넘침 유무와 별개로, 조작과 결과 사이 거리가 학습을 끊는다.

**개선:** 작은 화면은 핵심 설명 한 문장 → 주요 조작 → 도식·결과를 가까이 배치한다. 긴 입문 배경은 펼쳐 읽도록 하되 조작에 필요한 뜻은 계속 보여준다. 내부에 더 읽을 내용이 있다는 표식도 추가한다. 고정 헤더·하단 탐색의 점유 높이를 함께 재검토한다.

## C. 내용·자료 구성 개선

### 7. 실제 3D 구조와 논리 Page를 연결하는 보충 그림

**구분: 자료 보강 제안 / 우선순위 중간**

현재 글은 Page 층이 실제 반도체 층이 아니라는 점과 TLC에서 같은 Cell 집합이 여러 논리 Page를 표현한다는 점을 정확히 설명한다. 하지만 Article에도 그림이 없어 공간적 관계를 독자가 머릿속에서 재구성해야 한다.

**개선:** Article 02–03에 작은 비교 도식을 넣는다.

- 수직 채널, Wordline, Cell 위치를 보여주는 3D NAND 개념도.
- 같은 Cell 집합과 여러 논리 Page의 관계.
- 본편의 ‘동작 단위 도식’과 실제 구조가 무엇을 각각 설명하는지 짧은 캡션.

본편 장면 수를 늘리지 않고도 오해를 줄일 수 있다. 제조사·세대별 구체적인 층 수는 필요하지 않다. 구조 확인의 기준 자료는 [KIOXIA BiCS FLASH 설명](https://www.kioxia.com/en-jp/rd/technology/bics-flash.html)이다.

근거: `projects/nand-flash/content.mjs:72`, `content.mjs:77`.

### 8. 학습 후 남는 한 장 요약과 짧은 용어 정리

**구분: 자료 보강 제안 / 우선순위 중간**

현재 마지막 장면은 서사를 잘 닫지만, 배운 내용을 빠르게 복습하기 위한 정리는 부족하다. Article의 13개 절도 모두 세 문단 형식이어서 핵심만 다시 찾으려면 본문을 재독해야 한다.

**개선:** Article 시작 또는 마지막에 아래 내용을 짧게 묶는다.

- 전하 → Vth → 전류 판정 → bit.
- Read / Program은 Page, Erase는 Block.
- 수정 → 새 위치 기록 → Mapping → Invalid → GC.
- ECC는 검사 정보로 복구, Retry는 기준 전압을 바꿔 다시 읽기.

LBA / PPA / FTL / Vth / Vref는 한국어 한 줄 정의와 관련 장면 링크로 정리한다. 각 Article 절에는 ‘핵심 한 문장’을 추가하고, 06절은 동작 비교표, 07–08절은 전후 상태표처럼 내용에 맞는 형식을 사용한다. 선택적으로 ‘Invalid는 곧 Free일까?’ 같은 확인 질문 2–3개만 붙이면 학습 성취를 확인하기 좋다.

### 9. 특정 장면으로 돌아오고 공유하기 쉽게 만들기

**구분: 기능 개선 제안 / 우선순위 중간**

Article에는 앵커가 있지만 본편의 장면 이동은 스크롤 좌표만 바꾸고 URL은 바뀌지 않는다. 발표나 설명 중 특정 실험을 직접 공유하기 어렵다. 후반에는 상단 축척 탐색도 사라져 전체 학습 여정에서 현재 위치를 파악할 단서가 줄어든다.

**개선:** `#scene-gc` 같은 장면 링크와 복사 기능, 새로 열었을 때 해당 장면 진입을 제공한다. 후반에는 구조 계층 대신 ‘물리 → 공간 관리 → 신뢰성 → 전체 흐름’의 간단한 진행 표시를 검토한다. 링크는 장면 위치만 가리키고, 실험 상태 저장이 필요하면 별도로 범위를 정한다.

근거: `projects/nand-flash/main.js:233`, `main.js:209` 부근의 계층 표시 조건.

### 10. 출처를 ‘더 읽을 자료’로 안내하고 인쇄 활용성 보강

**구분: 선택적 자료 완성도 개선**

주제별 출처 링크는 이미 좋은 기반이다. 다만 원문은 입문 설명, 기술 PDF, 전문 논문이 섞여 있다.

**개선:** 각 출처에 ‘무엇을 확인할 수 있는지’ 한 줄을 붙이고, 입문/심화와 발행 연도·PDF 여부를 표시한다. 예를 들어 KIOXIA는 구조·동작 이해, Read Retry 논문은 심화 자료로 안내한다. 자료를 저장·배포해서 읽는 사용까지 고려한다면 Article 전용 인쇄 스타일도 유용하다. 현재 코드에는 별도 print 스타일이 없으며, 실제 인쇄 결과는 이번 검토 범위에 포함하지 않았다.
