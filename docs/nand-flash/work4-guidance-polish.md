# Work4 조작 안내·입문 설명·도식 개선

## 방향

22개 장면의 순서와 스크롤 탐험을 유지한다. 사용자가 현재 장면의 뜻, 조작할 곳, 조작 후 관찰할 변화를 화면 안에서 이해할 수 있도록 한다.

## 적용 순서

1. 모든 장면에 행동과 관찰 대상을 안내한다. 실행 버튼, 선택 버튼, 슬라이더, 도식 안의 이동 지점에 서로 다른 명확한 형태를 부여한다. GC 준비와 ECC 오류 만들기처럼 선행 동작이 필요한 경우 현재 상태에 맞춰 안내한다.
2. 본편에 짧은 배경 설명을 추가한다. 처음 등장하는 Cell, Vth, 주소, 상태, P/E, ECC 등을 한국어로 풀어 쓰고 Article로 넘어가지 않아도 인과관계를 이해할 수 있게 한다.
3. 컴퓨터는 실제 사용·내부 연결을 알아볼 수 있는 구조, Die는 저장 배열과 주변 회로가 구분되는 평면 배치, Page는 Cell 집합과 읽기 회로·데이터 묶음의 관계를 보여주는 공학 도식으로 발전시킨다. 치수·배치는 개념도임을 명시한다.
4. 데스크톱·모바일에서 설명과 조작부의 겹침, 키보드, 장면 전환, 주요 시뮬레이션을 확인한다. 기존 모델과 Article 검증, Pages 빌드를 통과한 결과를 기존 main 배포 경로로 반영한다.

## 구현 원칙

조작 설명은 hover 없이 보인다. 정적인 명시적 표식을 기본으로 하고 반복 점멸로 조작을 재촉하지 않는다. 상세 도식은 기능적 SVG로 구현해 선택·전원 상태와 연결한다. 모바일에서는 도식의 보조 라벨을 줄이고 본문·버튼의 글자 크기를 유지한다.

## 적용 결과와 검증

- 22개 장면 모두에 입문 설명과 조작 안내를 추가했다. 저장·Package·Program·GC·ECC 안내는 현재 상태에 맞게 바뀐다. GC 첫 방문에서 Invalid가 없으면 먼저 수정을 안내하고, 생기면 같은 주요 버튼이 GC 실행으로 바뀐다.
- 실행 버튼은 채워진 표면, 선택은 구획된 묶음, 이동은 화살표 표식을 사용한다. 그림의 SSD·Plane·Block·Page·Cell을 클릭하거나 키보드로 선택할 수 있다. 슬라이더에는 현재 상대값이 함께 표시된다.
- 컴퓨터에 키보드·힌지·연결 포트와 CPU/RAM/SSD 기판을 보강했다. Die에는 저장 배열·읽기 회로·주변 제어·입출력 연결부를, Page에는 Cell 배열에서 읽기 판정이 데이터 묶음으로 이어지는 관계를 그렸다. 배치·축척·Page의 논리적 의미에 관한 설명은 유지했다.
- 모바일에서 조작 버튼이 긴 설명과 그림 아래로 밀리지 않도록 그림보다 먼저 배치했다. 분포 그래프에는 별도의 읽을 수 있는 HTML 라벨과 확대된 그래프 영역을 사용한다.
- 브라우저에서 1280×800, 1280×720, 390×844, 320×568을 확인했다. 데스크톱 22개 장면의 설명·안내·버튼 표시와 하단 탐색 영역 분리, 작은 모바일 22개 장면의 수평 넘침 없음, 주요 구조 이동·전원·GC 준비 및 실행·전압 slider·ECC를 검증했다. 새 Die 선택 지점은 Enter로도 이동한다. 콘솔 오류·경고 0건.
- 독립 리뷰에서 안내 누락, 동작 연결, 물리 개념, 키보드와 반응형을 검토했다. 구조 그림의 중복 캡션과 작은 선택 지점, 모바일 CSS 우선순위를 정리했다.
- 통합 테스트 40개, Article 원고/HTML 일치 검사, Work4 ESLint, GitHub Pages 통합 빌드를 통과했다. Work1–3 및 공통 빌드·배포 파일은 변경하지 않았다.
