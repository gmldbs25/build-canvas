# Work4 · 보는 것만으로 이해하는 반복 설명

2026-09-16

## 사용자 방향

실험을 진행하기 위해 여러 버튼을 눌러야 하는 부담을 줄인다. 장면에 들어가면 설명 애니메이션이 저절로 반복되고, 보는 것만으로 원인과 결과를 이해하게 한다. 장면 이동 자체는 스크롤과 기존 탐색에 맡긴다.

## 구현

- 15개 동작 장면에 자동 루프를 적용했다. 첫 저장·정상 종료·재시작, 패키지 개방, 전하 유지, SLC–QLC, Program, Read, Erase, 주소 변환, FTL, GC, 마모 분산, Retention/Disturb, ECC/Retry, 전체 Write/Read가 대상이다.
- 시작 상태 → 변화 → 결과를 순서대로 보여주고 결과에 더 오래 머문다. 각 단계는 현재 동작을 설명하는 캡션과 진행선으로 구분한다. 복잡한 단계는 대체로 2.8–4.5초, 반복 펄스와 마모 추가는 1.4–1.5초다.
- 기본 화면의 실행 버튼·슬라이더는 `직접 살펴보기`로 접었다. 이를 열면 기존 실험을 사용할 수 있고, `자동으로 보기`로 루프를 다시 시작한다.
- 상단 재생 버튼은 장면 안의 움직임을 제어한다. 기존의 자동 스크롤 재생은 대체했다. 스크롤하지 않으면 다음 장면으로 넘어가지 않는다.
- Wear는 같은 초기 사용량·같은 P/E 6회를 나란히 적용한다. 각 결과에서 가장 많이/적게 사용한 Block의 차이를 보여준다.
- 모바일은 짧은 설명 → 도식 → 단계 해설 → 선택적 직접 조작 → 배경 설명 순서로 바꿨다. ECC 검사/데이터 라벨도 키웠다.

## 모델과 정확성

`demos.mjs`는 기존 모델 함수를 실행해 독립된 단계별 스냅샷을 만든다. 반복 재생은 해당 스냅샷을 보여줄 뿐, 직접 실험 상태를 변경하지 않는다. FTL의 마지막 저장 상태는 GC의 첫 상태와 같다. GC는 복사·주소 갱신을 마친 후에만 Erase된 스냅샷을 만든다. Write와 Read 역시 동일한 주소·버전 예시를 사용한다.

Read와 Read Retry는 모두 `Vref > Vth → 도통 → 1`로 해석한다. Retry의 표시점도 실제 모델에서 계산한 오류 Cell의 Vth를 사용한다. ECC 1 bit 복구, 2 bit 검출, 같은 전하의 재판정을 자동으로 보여준다. 전원 없이 상태가 남는다는 설명에는 정상 종료 가정과 영구 보존이 아니라는 조건을 유지한다. Page의 논리적 의미와 교육용 수치 범위도 유지한다.

Article의 버튼 중심 설명과 FTL/GC 상태 설명을 새로운 기본 흐름에 맞춰 갱신하고 HTML을 다시 생성했다.

## 재생 수명과 접근성

- 목차가 열렸을 때, 탭이 비활성일 때, Article에 있을 때, 도식이 화면 밖일 때, 장면 전환 중에는 반복 시계가 진행하지 않는다.
- 상단 일시정지 선택은 다음 장면에도 유지된다. Tab·Escape에 의한 키보드 탐색 정지는 현재 장면에만 적용된다.
- 동작 줄임 환경은 최종 대표 상태를 정지 화면으로 제공한다. 직접 살펴보기는 계속 사용할 수 있다.
- 자동 반복의 결과는 live region 알림을 반복하지 않는다. 직접 조작 결과는 기존 알림을 유지한다.
- 자동 설명 중 도식 안의 실험 버튼은 조작되지 않는다. 구조 탐험의 이동 지점은 유지한다.
